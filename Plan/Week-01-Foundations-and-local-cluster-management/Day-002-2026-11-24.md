## A · Controllers (2 engineers)

**Task:** Write `ClusterType` and `KubernetesCluster` types; generate CRDs.

**Steps**

1. Add `ClusterType` (cluster-scoped): provider, `ClusterClass` reference, allowed versions, sizes, allowed environments and stacks, add-ons.
2. Add `KubernetesCluster` (cluster-scoped): type, team, environment, size, version.
3. Add CEL validation rules (`@ValidationRule`) for names, sizes and versions.
4. Generate the CRDs at build time; write samples in `config/samples`.

**Output:** Cluster kinds with samples.

**Done when:** `./mvnw package` produces valid CRDs; samples apply to the local hub.

## B · Platform (1 engineer)

**Task:** Add the CAPD `ClusterClass` `ssp-docker`; create one local cluster by hand with `clusterctl`.

**Steps**

1. Take the Cluster API quick-start `ClusterClass` for the Docker provider; rename it `ssp-docker`; commit it to the `platform` fixture.
2. Generate a cluster with `clusterctl generate cluster --flavor development` and apply it.
3. Wait for the control plane and one worker; fetch its kubeconfig with `clusterctl get kubeconfig`.

**Output:** A hand-made local cluster.

**Done when:** `kubectl get nodes` on the new cluster shows ready nodes.

## C · Experience (1 engineer)

**Task:** Scaffold the `kubectl ssp` plugin (Picocli, GraalVM native binary) with `version` and contexts.

**Steps**

1. Create the `cli` module with Picocli (Quarkus Picocli extension).
2. Add `version` and `context` (reads kubeconfig contexts for np-hub and pr-hub through the Fabric8 client).
3. Build a GraalVM native binary with `./mvnw package -Dnative`; install into `PATH` as `kubectl-ssp`.

**Output:** `kubectl ssp version` works.

**Done when:** The plugin installs and prints its version and the current hub context.
